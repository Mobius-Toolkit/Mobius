# Antigravity CLI and Devin CLI gaps for Mobius

Date of research: 2026-09-26.

Versions examined:

- Antigravity CLI (`agy`) 1.2.11, tag `1.2.11`, commit `6dadd62` of `google-antigravity/antigravity-cli` [3][4].
- Official Antigravity ACP server (`agy_acp_server`) 1.2.1, registry id `antigravity-acp`, registry commit `3ee7f11` [5]. The file `agy-acp-server-1.2.1-darwin-arm64.zip` has SHA-256 prefix `0fab9938812e6b32`.
- Devin CLI 3000.11.3, public docs and stable changelog only [20]–[26].

Legend: **(V)** = verified in a primary source at the cited link, or in the Python source inside the Google-signed ACP server binary. **(U)** = unverified.

Note on method: Google publishes no source repository for the ACP server. The binary `agy_acp_server.par` contains its Python source as a ZIP archive. This note cites those files as `acp_server/<file>.py` [6]. A local probe with an isolated `GEMINI_HOME` confirmed the `initialize` result and the `session/new` auth error [7].

## Summary

Antigravity CLI (`agy`) is a new, closed-source Google product in Go, not a rename or a fork of Gemini CLI. It replaced Gemini CLI for Google AI Pro, Ultra, and free users on 2026-06-18 (V [1][2]). Thus the earlier Gemini CLI research no longer applies to subscription use. The `agy` binary has no ACP mode, and the public feature request is open (V [4][8]). Google ships a separate official ACP server, `agy_acp_server` 1.2.1, which drives the same Antigravity agent harness over ACP v1 on stdio (V [5][6][7]). It supports `session/new`, `session/load`, `session/resume`, `session/list`, `session/prompt`, `session/cancel`, `session/request_permission`, streamed updates, and config options for model and mode. It does not advertise `session/close` (V [6][7]). It accepts HTTP and SSE MCP servers with literal `headers` from `session/new`, and mode `yolo` approves all tools, MCP tools included (V [6]). The main risk is legal: the terms forbid "third party software, tools, or services to access the Service", and Google gives no clear rule for a self-hosted orchestrator (V quote [9][10]; U interpretation). For Devin, the public docs close only part of the earlier gaps; deferral, timeouts, and exact `tool_call` fields stay open (V/U [20]–[26]).

## Impact on earlier decisions

- Gemini CLI with a Google AI Pro or Ultra login stopped on 2026-06-18 (V [1]). Replace the Gemini CLI Harness with the Antigravity ACP server.
- The launch command changes from `gemini --acp` to the registry binary `agy_acp_server.par` (Linux adds `--uid=`) (V [5]).
- The Gemini-specific rules in the transport note no longer apply: `GEMINI_CLI_TRUST_WORKSPACE`, stdio env redaction, and `$VAR` expansion in headers. The ACP server passes headers literally (V [6]).
- HTTP MCP inside the Mobius server stays valid: the ACP server accepts `headers` per session (V [6][7]).
- Mobius must set mode `yolo` after each `session/new` and `session/load`, because new sessions start in `default` (V [6]).
- The Mobius MCP server must be up before `session/new`. A failed MCP handshake makes every prompt of that session fail (V [6]).

## Open points for a spike

1. Terms: ask Google in writing whether a self-hosted, single-Owner orchestrator may drive the unmodified `agy_acp_server` with a personal AI Pro/Ultra login. Do not ship the Harness before an answer.
2. Deferral: run a real session with the Mobius HTTP MCP server. Record whether the model calls `call_mcp_tool` without a schema read, and how often it fails.
3. Deferral switch: test `tools.eager` and `omitFromSystemPrompt` in `$GEMINI_HOME/config/mcp_config.json` for a server with the same name. The ACP server parses only `command`, `args`, `env`, `url`, and `headers`, so expect no effect.
4. Headers: confirm that the Go harness sends the `Authorization` header unchanged, with no `${VAR}` or `$VAR` expansion.
5. Timeouts: measure the per-call MCP timeout of the harness. Measure the time before `session/new` fails for an unreachable MCP server.
6. Env: confirm which env the harness gives to `run_command` and to stdio MCP servers.
7. Auth on a headless host: test `authenticate` with `oauth-personal` through an SSH port forward to the loopback redirect. Confirm the token refresh in `acp_token.json`.
8. Tier: confirm which tier governs quota and data use for ACP sessions. A community report shows `currentTier: free-tier` next to `paidTier: g1-pro-tier` [8].
9. Workspace: confirm that file tools cannot reach a second worktree, because `additionalDirectories` is ignored. Plan one session per worktree `cwd`.
10. Session end: `session/close` does nothing, so Mobius must end the process to free a session. Confirm memory use with many sessions in one process.
11. Devin: confirm env inheritance from the host process, MCP deferral, per-call MCP timeout, header env expansion, and `tool_call` `kind`/`rawInput` for an MCP tool.
